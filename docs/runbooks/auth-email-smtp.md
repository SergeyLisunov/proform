# Runbook — Supabase Auth email (Resend SMTP) + password reset

Owner action required. These are **Supabase Dashboard** settings (secrets +
project config), not code — they can't be applied from the repo or via MCP.

Project: `atlet-pro` (`hhyjihbctidtucvpgjzv`, eu-central-1).

---

## Why this matters

By default Supabase Auth sends confirmation / recovery emails through its
**built-in SMTP**, which is **rate-limited to a few messages per hour** and is
explicitly "for testing only". At any real signup volume new users silently
stop receiving confirmation / reset emails.

`Resend` is already used for the app's own transactional mail (`lib/email/*`)
but is **not** wired into Supabase Auth. The two are separate: app mail goes
through the Resend API; Auth mail (confirm signup, reset password, magic link)
goes through whatever SMTP the Auth service is configured with.

---

## 1. Custom SMTP — point Auth at Resend

Dashboard → **Authentication → Emails → SMTP Settings** → enable **Custom SMTP**:

| Field            | Value                                              |
| ---------------- | -------------------------------------------------- |
| Sender email     | `no-reply@<your-verified-resend-domain>`           |
| Sender name      | `Sporteo`                                          |
| Host             | `smtp.resend.com`                                   |
| Port             | `465` (SSL/TLS) — or `587` / `2587` for STARTTLS   |
| Username         | `resend`                                            |
| Password         | a Resend **API key** (`re_…`) with send permission |

Requirements:
- The sender **domain must be verified in Resend** (SPF + DKIM records added to
  DNS). Resend → Domains → confirm "Verified" before saving here.
- Don't reuse a personal Gmail as the sender — it won't pass DKIM for the domain
  and will land in spam.

> The API key is a **secret** — paste it directly into the dashboard. Do **not**
> commit it to the repo or `.env`.

---

## 2. Redirect URLs — required for the password-reset flow

The reset link generated by `resetPasswordForEmail` redirects to
`<origin>/auth/reset`. Supabase only honours redirect targets on its allow-list,
so add them or the link will bounce to the Site URL.

Dashboard → **Authentication → URL Configuration**:

- **Site URL:** `https://proform-delta.vercel.app`
- **Redirect URLs** (add all):
  - `https://proform-delta.vercel.app/**`
  - `http://localhost:3000/**` (local dev)
  - `https://*-<your-vercel-scope>.vercel.app/**` (branch/preview deploys, optional)

The `/auth/reset` and `/auth/forgot` routes already exist in the app (added with
the password-reset feature).

---

## 3. Rate limits

Dashboard → **Authentication → Rate Limits** → raise **"Number of emails sent
per hour"** from the built-in default (low) to a value matching expected signup
volume now that a real provider (Resend) is behind it.

---

## 4. Email templates (optional but recommended)

Dashboard → **Authentication → Emails → Templates**. Localise to Russian +
Sporteo branding for at least:
- **Confirm signup** — must keep `{{ .ConfirmationURL }}`
- **Reset password** — must keep `{{ .ConfirmationURL }}`

---

## 5. Verify after configuring

1. **New-user email:** register a brand-new address on
   `https://proform-delta.vercel.app/auth/register` → confirmation email should
   arrive within seconds (check Resend → Logs for the send).
2. **Reset email:** `https://proform-delta.vercel.app/auth/forgot` → enter a
   real account email → reset email arrives → link opens `/auth/reset` → set a
   new password → log in.
3. **Auth logs:** Supabase → Logs → Auth. A successful send is logged; SMTP
   failures show up here with the provider error.
