# Telegram-бот Sporteo — полный runbook запуска

Пошаговая инструкция «от нуля до работающего зеркала уведомлений».
Код уже в проде (PR #223, миграция 099 применена к Supabase) — этот
документ закрывает всё, что делается РУКАМИ: BotFather, env, вебхук,
крон очереди, проверка и диагностика.

---

## Как это устроено (2 минуты на прочтение)

Бот — **не отдельный сервис**, а часть Next.js-приложения. Никакого
второго процесса поднимать не нужно: Telegram сам приходит к нам по
HTTPS (webhook-режим). Компоненты:

| Компонент | Где | Что делает |
|---|---|---|
| `POST /api/telegram/webhook` | роут приложения | принимает апдейты от Telegram (команды /start, /unlink, /help); подлинность — заголовок `X-Telegram-Bot-Api-Secret-Token` |
| `POST /api/telegram/link` | роут приложения | генерирует одноразовую ссылку привязки (в БД — только SHA-256-хэш кода, TTL 10 мин, ≤5/час) |
| Триггер `trg_enqueue_telegram` | Supabase (миграция 099) | на каждый INSERT в `notifications` кладёт задание в очередь `telegram_deliveries` — но ТОЛЬКО если пользователь привязал TG **и** явно включил тумблер «Telegram» |
| `GET /api/telegram/process-queue` | роут приложения | отправляет очередь в Telegram (батч 40, пауза 50 мс, 5 попыток); дёргается кроном раз в минуту |
| Карточка + тумблер | «Настройки → Уведомления» | привязка/отвязка и opt-in зеркала |

Поток данных:

```
событие в платформе → INSERT notifications
                    → триггер 099 (привязан? тумблер включён?)
                    → telegram_deliveries (status=queued)
                    → крон дёргает /api/telegram/process-queue
                    → sendMessage: ЗАГОЛОВОК + кнопка «Открыть в Sporteo»
```

Два жёстких правила приватности (уже зашиты в код, не ослаблять):

1. **В Telegram уходит только заголовок уведомления и ссылка.** Тело —
   никогда: там могут быть мед-статусы и данные детей, а сообщение в
   TG живёт вне нашего контроля (форвард, скриншот).
2. **Привязка ≠ подписка.** После привязки не отправляется ничего,
   пока пользователь сам не включит тумблер «Telegram» (чистая история
   согласия по 152-ФЗ).

## Шаг 0. Что понадобится

- Телефон с Telegram (создать бота).
- Доступ к переменным окружения приложения:
  - сейчас — Vercel → Project Settings → Environment Variables;
  - после переезда — `/srv/sporteo/.env` на VPS (см. HOSTIMAN.md).
- Значение `CRON_SECRET` (уже есть в env приложения).
- 15 минут.

---

## Шаг 1. Создать бота в BotFather

1. В Telegram откройте **@BotFather** (проверьте синюю галочку).
2. Отправьте `/newbot`.
3. **Имя** (отображаемое): `Sporteo` — можно с пробелами, менять легко.
4. **Username**: должен заканчиваться на `bot` и быть свободен,
   например `SporteoBot` или `sporteo_platform_bot`.
   ⚠️ Запишите его БЕЗ `@` — это будущий `TELEGRAM_BOT_USERNAME`
   (ссылки привязки строятся из него; опечатка = ссылки в никуда).
5. BotFather пришлёт **токен** вида `1234567890:AA...`. Это
   `TELEGRAM_BOT_TOKEN`. Токен = полный контроль над ботом:
   никуда не постить, хранить только в env. Если утёк — в BotFather
   `/revoke` и замените в env.

Сразу приведите бота в порядок (всё в том же чате BotFather):

6. `/setdescription` → выберите бота → текст, который видят до нажатия
   Start, например:
   > Официальный бот платформы Sporteo. Привязка аккаунта и уведомления: расписание, допуски, достижения. Привязка — из приложения: Настройки → Уведомления.
7. `/setabouttext` → короткая строка для профиля: `Уведомления платформы Sporteo`.
8. `/setjoingroups` → **Disable** — бот работает только в личке,
   в группы его добавлять незачем (и код игнорирует не-приватные чаты).
9. `/setprivacy` → **Enable** (бот не читает чужие сообщения; для
   лички не важно, но правильный дефолт).
10. Опционально `/setuserpic` — логотип Sporteo.

Меню команд можно не настраивать вручную — его поставит скрипт из шага 3.

## Шаг 2. Переменные окружения

Сгенерируйте секрет вебхука (любая машина с openssl):

```bash
openssl rand -hex 32
```

Добавьте в env приложения (Vercel: Settings → Environment Variables →
Production; позже на VPS — те же строки в `/srv/sporteo/.env`):

```bash
TELEGRAM_BOT_TOKEN=1234567890:AA...        # из шага 1.5
TELEGRAM_BOT_USERNAME=SporteoBot           # из шага 1.4, БЕЗ @
TELEGRAM_WEBHOOK_SECRET=<из openssl выше>
```

⚠️ На Vercel после добавления переменных нужен **redeploy** (Deployments
→ последний → Redeploy), иначе роуты продолжат отвечать 503
`TELEGRAM_NOT_CONFIGURED`.

Проверка, что приложение увидело конфиг:

```bash
curl -s https://<домен>/api/telegram/webhook | python3 -m json.tool
# ожидаем: { "ok": true, "endpoint": "...", "configured": true }
```

`configured: false` → переменные не подхватились (не тот environment,
не было redeploy).

## Шаг 3. Зарегистрировать вебхук — одной командой

В корне репозитория (или на любой машине с bash/curl; с RU-хостинга
может не сработать из-за фильтрации api.telegram.org — тогда с
локальной машины):

```bash
TELEGRAM_BOT_TOKEN='1234567890:AA...' \
TELEGRAM_BOT_USERNAME='SporteoBot' \
TELEGRAM_WEBHOOK_SECRET='<тот же, что в env приложения>' \
APP_URL='https://proform-delta.vercel.app' \
  bash deploy/telegram-setup.sh
```

Скрипт: проверит токен и username (ловит опечатку до того, как она
сломает ссылки), зарегистрирует вебхук с `secret_token` и
`drop_pending_updates`, поставит меню команд, покажет `getWebhookInfo`.

В `getWebhookInfo` смотрите:

- `"url"` — ровно `https://<домен>/api/telegram/webhook`;
- `"pending_update_count": 0`;
- **отсутствие** `last_error_message`.

Ручная альтернатива (если скрипт недоступен):

```bash
curl "https://api.telegram.org/bot$TOKEN/setWebhook" \
  -d url=https://<домен>/api/telegram/webhook \
  -d secret_token=$TELEGRAM_WEBHOOK_SECRET \
  -d drop_pending_updates=true
```

⚠️ Домен должен иметь **CA-signed** сертификат (Vercel/Let's Encrypt —
ок; self-signed Telegram молча отвергает).

## Шаг 4. Крон очереди — чтобы уведомления реально уезжали

Команды бота (/start, /unlink) работают сразу после шага 3 — они
синхронные. А вот **зеркало уведомлений** лежит в очереди, пока её не
обработает `/api/telegram/process-queue`. Vercel минутные кроны не
умеет, поэтому эндпоинт дёргается извне:

**Вариант А — уже есть любой свой сервер/VPS (в т.ч. будущий Hostiman
ещё ДО переезда приложения):** одна строка в `crontab -e`:

```cron
* * * * * curl -fsS -H "Authorization: Bearer <CRON_SECRET>" https://<домен>/api/telegram/process-queue >> /var/log/sporteo-tg.log 2>&1
```

**Вариант Б — после переезда на Hostiman:** ничего отдельно делать не
надо, строка уже включена в `deploy/crontab.sample`.

**Вариант В — временно, руками:** дернуть эндпоинт вручную и убедиться,
что всё работает:

```bash
curl -s -H "Authorization: Bearer <CRON_SECRET>" \
  https://<домен>/api/telegram/process-queue | python3 -m json.tool
# ожидаем: { "ok": true, "batch": N, "sent": N, "failed": 0, "skipped": 0 }
```

Сторонние cron-сервисы НЕ используйте: пришлось бы отдать им
`CRON_SECRET`, который защищает и остальные кроны платформы.

## Шаг 5. Привязка аккаунта — пользовательский флоу

Так это выглядит для любого пользователя (проверьте сами на своём
аккаунте):

1. Приложение → **Настройки → Уведомления**.
2. Карточка «Telegram-бот» → кнопка **«Подключить»**.
3. Появляется кнопка **«Открыть бота и подтвердить»** — это ссылка
   `https://t.me/<бот>?start=<одноразовый код>`. Она живёт 10 минут
   и срабатывает один раз.
4. Telegram открывает чат с ботом → нажать **Start** (или «Запустить»).
5. Бот отвечает: *«Готово — Telegram привязан к аккаунту «Имя»…»*.
6. Вернуться в настройки, обновить страницу — карточка показывает
   «Привязан: @username», кнопка меняется на «Отвязать».

Если бот ответил «Ссылка недействительна или устарела» — код истёк
(10 мин) или уже использован: сгенерируйте новый кнопкой «Подключить».

## Шаг 6. Включить зеркало и прогнать сквозной тест

1. Там же в настройках включите тумблер **«Telegram»** (группа
   «Основные»). По умолчанию он ВЫКЛ у всех — это осознанно.
2. Спровоцируйте любое уведомление. Самый простой способ: со второго
   аккаунта (тренер) назначьте первому (атлет) тренировку — атлету
   создастся уведомление «Тренер назначил тренировку».
3. Подождите крон (до минуты — вариант А) или дёрните эндпоинт руками
   (вариант В).
4. В Telegram придёт сообщение: **заголовок** уведомления + кнопка
   **«Открыть в Sporteo»**, ведущая на нужный экран приложения.

Диагностика по базе (Supabase → SQL Editor), если что-то не пришло:

```sql
-- привязка есть?
select user_id, tg_username, linked_at, unlinked_at
from telegram_accounts order by linked_at desc limit 5;

-- тумблер включён? (должно быть true)
select notification_prefs->>'telegram'
from users where id = '<user_id>';

-- задание встало в очередь и в каком оно статусе?
select status, attempts, last_error, title, created_at
from telegram_deliveries order by created_at desc limit 10;
```

Чтение статусов очереди: `queued` — ждёт крон; `sent` — доставлено;
`skipped` — пользователь заблокировал бота (или удалил чат) — это
терминально, отправка ему остановлена; `failed` — 5 неудачных попыток,
причина в `last_error`.

## Траблшутинг

| Симптом | Причина | Лечение |
|---|---|---|
| `configured: false` на `/api/telegram/webhook` | env не подхвачен | проверить окружение (Production?) и сделать redeploy |
| Бот молчит на /start | вебхук не зарегистрирован или смотрит на старый домен | `getWebhookInfo`; перезапустить шаг 3 |
| `getWebhookInfo` → `last_error_message: "Wrong response..."` или 401 | `secret_token` в setWebhook ≠ `TELEGRAM_WEBHOOK_SECRET` в env приложения | выставить одинаковые значения, повторить setWebhook |
| Бот отвечает, но «Не получилось привязать аккаунт» | нет `SUPABASE_SERVICE_ROLE_KEY` в env / сбой БД | проверить env и логи функции |
| Уведомления не приходят, очередь `queued` растёт | крон не дёргает process-queue | шаг 4; проверить `CRON_SECRET` в заголовке |
| process-queue возвращает 401 | неверный `CRON_SECRET` в crontab | сверить со значением в env приложения |
| Всё настроено, но `telegram_deliveries` пустая | тумблер «Telegram» выключен (дефолт!) или привязка снята | SQL-запросы из шага 6 |
| `skipped` в очереди | пользователь заблокировал бота | норма; пользователь может привязаться заново |
| С сервера не доступен api.telegram.org (timeout) | RU-ЦОД, DPI-фильтрация Telegram (2025–2026) | выполнять настройку с локальной машины; хостить на EU-локации (HOSTIMAN.md §0) |
| Ссылка привязки ведёт на чужого/несуществующего бота | опечатка в `TELEGRAM_BOT_USERNAME` | исправить env (скрипт шага 3 ловит это заранее) |

## Переезд на Hostiman: что изменится

Почти ничего — бот живёт внутри приложения:

1. Те же три `TELEGRAM_*`-переменные в `/srv/sporteo/.env`.
2. После смены домена — **один раз** перезапустить шаг 3 с новым
   `APP_URL` (setWebhook перепишет адрес; старый снимать не нужно).
3. Крон очереди уже в `deploy/crontab.sample`.
4. Локация VPS — **только Европа** (из RU-ЦОД api.telegram.org
   фильтруется, причём ломаются и вебхуки, и исходящие вызовы).
