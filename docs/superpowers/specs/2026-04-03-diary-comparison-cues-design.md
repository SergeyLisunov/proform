# Diary Comparison Cues Design

## Goal

Усилить athlete diary коротким polish-pass, чтобы карточки тренировок показывали не только текущие метрики, но и сравнение с предыдущей тренировкой того же типа.

## Scope

- Для каждой тренировки находить предыдущую запись с тем же `activity_type`.
- Показывать compact comparison cues в list и grid карточках.
- Сравнивать только уже существующие клиентские данные: `activity_strain`, `activity_duration_min`, `avg_heart_rate`.
- Добавлять мягкий neutral state, если сравнить запись не с чем.

## Non-Goals

- Не менять БД, Supabase-запросы и shape `Workout`.
- Не трогать coach diary.
- Не переносить comparison UI в drawer на этом проходе.

## UX Direction

Comparison cues должны усиливать считывание карточки, а не превращать ее в отдельный analytics-block. Пользователь должен быстро понимать:

- тяжелее или легче была текущая сессия;
- длиннее или короче она стала;
- как изменилась средняя ЧСС, если данные есть.

## Data Rules

- Источник сравнения: предыдущая по времени тренировка того же `activity_type`.
- Если предыдущей записи нет, показываем `первая запись этого типа`.
- Если предыдущая запись есть, но метрик для сравнения недостаточно, показываем мягкое сообщение про отсутствие сравнимых данных.
- Thresholds остаются компактными и UX-ориентированными, без сложной аналитики.

## Success Criteria

- В list/grid карточках появляется понятный comparison row.
- Comparison cues не ломают текущую иерархию карточек на desktop и mobile.
- `eslint` и `npm run build` проходят без регрессий.
